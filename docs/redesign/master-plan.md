# Мастер-план редизайна: этапы, трекер, делегирование

Единая точка входа для координатора и агентов. Подробности задач — в [dev-plan.md](dev-plan.md), экраны —
в [screens.md](screens.md), правила визуала — в [design-system.md](design-system.md), макеты — в
[mockups/v2/](mockups/v2/index.html). Готовые брифы для агентов — в [briefs/](briefs/).

**Источник правды — макеты v2.** `mockups/v2/*.html` и общие файлы рядом с ними (`tokens.css`, `shared.css`,
`figures.js`, `hero.js`, `scroll.js`, `device.js`, `theme.js`). Старый прототип `mockups/app.html` — только
исторический референс, по нему не верстаем.

## 3. Зависимости и точки стыка

- **WP1 → все.** Остальные стартуют от влитого WP1 (или от его ветки, если ждать нельзя, с последующим ребейзом).
  WP1 оставляет страницы-заглушки с маршрутами из screens.md, чтобы ветки собирались.
- **WP3 → WP2.** До мерджа WP3 экран Круга использует текущий `NetworkGraph` как есть. После мерджа WP2 подключает
  пропсы `onNodeTap`, `highlightPath`, `hiddenRings`, `focusOnMe`, `theme` короткой правкой.
- **WP1 ↔ WP4.** Таб «Просьба» с кольцом прогресса рисует WP1 по двум числам (доля круга, доля сети); WP4 даёт числа
  из `connection.getNetworkStats` и включает состояние.
- **WP7 ↔ WP10.** Фигуры (`netFigure`, кольцо хуэй, кольца рукопожатий, цепочки) переносятся из `mockups/v2/figures.js`
  в `apps/web/src/components/figures/*` пакетом WP7; WP10 использует их же на главной и `/how`. Сцена hero
  (`mockups/v2/hero.js`) — только WP10.
- **WP4 ↔ WP10.** Публичная страница сбора `/sos/:id`: содержимое делает WP4, обёртку-панель сайта на ширине от
  1024 — WP10 (`Panel` из `components/site/*`).
- **WP5 → WP10.** Ссылка «Как это работает» из Помощи ведёт на `/how` (WP10).
- **Общие файлы** (`App.tsx`, `Layout.tsx`, `tokens.css`, `tailwind.config.js`, локали) — только у владельца (WP1,
  локали — своя секция у каждого). Нужна правка чужого файла — запрос координатору или ожидание мерджа.

## 5. Этап 0: база ветки

```bash
git checkout redesign
git merge --ff-only origin/redesign-mockups   # документы и макеты
git merge origin/main                         # пять коммитов прода (graph-3d, вехи)
pnpm install && pnpm build
git push origin redesign
```

В `main` не пушить. Если мердж `main` конфликтует в `packages/graph-3d`, брать версию `main`: WP3 всё равно
переписывает граф.

## 6. Как делегировать агенту

1. Координатор создаёт локальную ветку и worktree рядом с репозиторием:
   `git worktree add -b redesign-wpN-<имя> ../so-wpN redesign` (имена через дефис: при существующей ветке `redesign`
   git не даёт создать `redesign/...`). Интеграционный worktree на `redesign` — `../so-redesign`.
2. Исполнитель получает бриф `docs/redesign/briefs/wpN.md` целиком и рамки: путь worktree, без `push`, `checkout` и
   правок `main`, коммиты локально. Grok запускается так:
   `grok -m grok-4.7-build-fast --cwd ../so-wpN --always-approve --deny "Bash(*git push*)" --deny "Bash(*git checkout*)"
   --deny "Bash(*git switch*)" --deny "Bash(*rm -rf*)" --deny "Bash(*curl*)" --prompt-file <бриф+рамки>`.
   Claude — субагент координатора с тем же брифом и рамками.
3. Исполнитель коммитит в свою ветку, отмечает чек-лист в своём брифе и сдаёт отчёт: что сделано, решения, что не
   сделано, удалённый код.
4. Ревью: субагент Sonnet 5.5 читает дифф `redesign...redesign-wpN-<имя>`; замечания уходят исполнителю на правку.
5. Координатор проверяет `pnpm typecheck`, `pnpm build`, экраны в браузере (390 / 834 / 1280, обе темы, с телефона по
   локальной сети), вливает ветку в `redesign` (`--no-ff`), удаляет ветку и worktree, обновляет трекер и пушит
   `redesign`. Рабочие ветки в GitHub не пушатся.

Правила для всех агентов (из dev-plan.md §1): ветка от `redesign`, в `main` не пушить, только семантические
токены, тексты через локали, комментарии и коммиты по-английски, `pnpm typecheck` чист, старый заменённый код
удалён или помечен `@deprecated`.
