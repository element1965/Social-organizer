# План разработки редизайна (для нескольких агентов)

Цель — переверстать `apps/web` под структуру из [screens.md](screens.md) и прототипа `mockups/app.html`,
не трогая бэкенд без необходимости. Работа ведётся несколькими агентами параллельно; этот документ — единый
источник задач, границ и правил, чтобы агенты не мешали друг другу.

## 1. Правила для всех пакетов

**Ветки.** База — `redesign`. Каждый пакет работ — своя ветка `redesign/wpN-<имя>` от `redesign`, PR в `redesign`.
В `main` ничего не уходит: push в `main` автоматически деплоит продакшен и нативные обёртки грузят прод-URL.

**Владение файлами.** У каждого пакета свой список файлов (ниже). Общие файлы (`App.tsx`, `Layout.tsx`, `tokens.css`,
`tailwind.config.js`, локали `packages/i18n/locales/*.json`) меняет только тот пакет, которому они назначены;
остальные добавляют новые файлы и просят владельца о правке через PR-комментарий или ждут мерджа. Если нужен новый
ключ локали — добавлять в **конец** секции своего экрана в `ru.json` и `en.json`, остальные 26 языков заполняет WP8.

**Стиль кода.** React 19 + Vite + Tailwind, компоненты в `apps/web/src/components/ui2/` (новый набор, старый `ui/`
не трогаем до WP9). Только семантические токены, никаких `gray-*`/`blue-*`/hex/`dark:`. Комментарии в коде по-английски,
сообщения коммитов по-английски. Все тексты через `useTranslation`, никаких строк в разметке.

**Данные.** Использовать существующие tRPC-процедуры (список в screens.md у каждого экрана). Новые поля API — отдельной
правкой в `apps/api`, с миграцией только если без неё нельзя; миграции применяются вручную (см. CLAUDE.md).

**Проверка.** Локально: `pnpm dev` (web :3000, api :3001), тестовые аккаунты из `packages/db/prisma/seed-dev.ts`:
`anna@test.local` (сеть из 18 человек, открытые сборы, заявка), `new@test.local` (пустой), `maria@test.local`
(автор срочного сбора). Код входа — в `%TEMP%\so-dev-mail.log`. Каждый пакет сдаётся со скриншотами своих экранов
в светлой и тёмной теме на ширине 390 px и с `pnpm typecheck` без ошибок.

**Определение готовности пакета.** Экраны совпадают с прототипом по составу и порядку элементов; все состояния из
screens.md реализованы (пусто, загрузка, ошибка); тексты из локалей; нет сырых цветов; старый код, который пакет
заменяет, удалён или помечен `@deprecated` с указанием заменяющего компонента.

### WP3 — 3D-граф: производительность и визуал

**Файлы:** `packages/graph-3d/src/NetworkGraph.tsx` (и новые файлы рядом), `packages/graph-3d/package.json`.
Не трогает `GlobeNetwork` (лендинг) и страницы web.

**Сделать** по ux-audit §8:
1. Общие геометрии и материалы на уровень детализации и цвет глубины; одна геометрия колец онлайна.
2. Подписи только у N ближайших к камере узлов и у подсвеченного пути; для 3-го кольца подписей нет.
3. Один тик анимации для всех пульсов онлайна; пересчёт LOD раз в 5–10 кадров.
4. Кэш координат узлов (IndexedDB через `@so/gun-backup` или `localStorage`), симуляция только для новых узлов.
5. Пауза рендера после остановки симуляции без жестов; возобновление по pointer/touch и смене данных.
6. `setPixelRatio(min(dpr, 2))`; прямые линии для 2–3 кольца, кривые только у подсвеченного пути.
7. Палитра из токенов (цвета передаются пропсами из CSS-переменных: `ink`, `ink-muted`, `ink-subtle`, `care`, `sos`,
   `canvas`), фон под тему, центральный узел — знак приложения, подписи Manrope с обводкой цвета канвы,
   приглушение всего кроме пути при фокусе, убрать «GoodWill Net», мышиную подсказку и английскую легенду;
   тултип по тапу в стиле карточки (имя, «N-е рукопожатие · через X», «Открыть»).
8. Жесты: один палец — вращение, два — зум/панорама, инерция; `prefers-reduced-motion` отключает дрейф и пульс.
9. Пропсы: `onNodeTap`, `highlightPath`, `hiddenRings`, `focusOnMe` (ref), `theme`.

**Готово, когда** синтетический набор 100 прямых + 300 дальних держит 60 fps при вращении на среднем Android
(замер в Chrome DevTools с троттлингом CPU ×4 — не ниже 30 fps), первая отрисовка < 1 с на тёплом кэше,
в покое `requestAnimationFrame` не вызывается; размер чанка `graph-3d` измерен и записан в PR.

## 3. Порядок и параллельность

```
WP1 ──┬── WP2 ──┐
      ├── WP3 ──┤  (WP3 независим от WP1, может стартовать сразу)
      ├── WP4 ──┤
      ├── WP5 ──┼── WP8 ── WP9
      ├── WP6 ──┤
      └── WP7 ──┘
```

WP3 не трогает `apps/web` и может идти с первого дня. WP2 использует текущий `NetworkGraph` до готовности WP3,
интеграция новых пропсов — короткая правка в WP2 после мерджа WP3.
